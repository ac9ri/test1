## 요약

- 목적: Agent의 실행 주체와 사내 GLM-5.3-Flash 연결 경로를 결정한다.
- 현재 결론 또는 상태: 실행 주체는 웹 백엔드(FastAPI)다. LLM은 백엔드가 OpenAI 호환 API로 호출하며, API가 없거나 실패하면 브라우저에서 해석 프롬프트를 복사해 사내 채팅 프로그램에 붙여넣고 답을 다시 붙여넣는 수동 경로를 P0로 둔다. 승인 대기.
- 다음 행동: 설계 승인과 함께 `approved`. 해커톤 시작 30분 안에 API 탐침(Q-07).

## 배경

2026-10-13 사용자 결정으로 목표가 MCP 도구 서버에서 웹 개발로 바뀌었다. 웹 앱의 백엔드가 LLM을 쓰려면 프로그램에서 호출할 수 있는 API가 필요한데, 사용자가 아는 접근 경로는 "클로드 데스크톱 같은 사내 프로그램"뿐이고 API 존재는 미확인이다(C-02). 해커톤은 12시간이며 클로드를 쓸 수 없다. 공개 사양상 GLM-5.3-Flash는 이미지 입력·함수 호출·JSON 출력을 지원하고, Z.ai와 주요 게이트웨이는 OpenAI 호환 형식을 제공한다.

## 고려한 대안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 백엔드가 OpenAI 호환 API로 LLM 호출(판별 보조·서술·채팅) | 완전 자동, 웹 Agent로서 자연스러움, 모델 교체 쉬움 | API가 없으면 동작 불가 |
| B | 사내 호스트 프로그램 + MCP 도구 서버(2차 초안) | LLM 클라이언트 불필요 | 웹 개발이라는 목표와 불일치. 대체됨 |
| C | 웹 앱은 결정적 분석만 하고 LLM 부분은 수동 복사·붙여넣기 | 어떤 환경에서도 시연 가능 | Agent라 부르기 어렵고 수동 단계가 남음 |
| D | 브라우저에서 직접 LLM API 호출 | 백엔드 단순 | 키 노출, CORS, 이미지 전송 통제 불가. 거부 |

## 결정

A를 기본(auto 모드)으로 하고 C를 수동 대체 경로(manual 모드)로 P0에 포함한다. 둘은 같은 화면·같은 코어를 쓰며 서술 출처만 다르다.

- `LlmClient` 프로토콜과 `OpenAICompatibleClient`, `MockLlmClient`를 둔다. `GLM_BASE_URL`이 없으면 클라이언트는 `None`이고 백엔드는 manual 모드로 동작한다.
- 구조화 출력은 `json_schema` → `json_object` → 프롬프트 JSON 추출 순으로 대체하고 pydantic으로 검증한다. 어떤 경로를 쓸지는 시작 시 `probe()`로 정한다.
- 이미지는 Base64 Data URL로 1024px 프리뷰만 보낸다. 키는 환경 변수로만 받는다(NFR-02).
- 수동 경로: 백엔드가 서술 호출과 동일한 프롬프트를 텍스트로 제공하고, 사용자가 붙여넣은 서술을 받아 보고서를 재생성한다.
- 호스트 프로그램 연동(B)은 설계 이력으로만 보존한다. 이후 MCP가 다시 필요해지면 같은 코어 위에 도구 서버를 얇게 올린다.

## 결과

- 장점: API 유무와 무관하게 시연이 된다(RISK-03). API가 확인되면 코드 변경 없이 환경 변수만으로 auto 모드가 된다. 프런트엔드·코어는 모드와 무관하다.
- 감수할 단점: manual 모드에서는 사람이 두 번 붙여넣어야 한다. auto 모드는 사내 API의 기능 지원 범위에 따라 대체 경로를 타며 지연이 늘 수 있다.
- 영향 범위: DES-08, DES-10, DES-12, 설계 2.3·5절, FR-12, FR-13, AC-13, AC-15. 2차 초안의 MCP 서버·호스트 시스템 프롬프트는 제거된다.
